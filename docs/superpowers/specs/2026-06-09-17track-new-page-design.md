# 17TRACK 新版英文页查询设计

## 背景

当前项目中的 `query_17track` 仍然使用旧版中文首页：

`https://www.17track.net/zh-cn`

流程是先打开首页，再向输入框填单号，点击查询，最后从页面中提取轨迹。

用户现在提供了新版英文直达页结构，地址为：

`https://t.17track.net/en#nums=<tracking_no>`

页面中已直接渲染轨迹时间线，不再需要先走旧首页的输入框交互。

## 目标

- 将 `query_17track` 切换到新版英文直达页。
- 保持返回结构不变：
  - `平台`
  - `查询值`
  - `当前页面标题`
  - `当前URL`
  - `最新轨迹`
  - `物流轨迹`
- 直接解析新版时间线中的 `时间 + 内容`。

## 非目标

- 不改动 `query_17track` 的函数名和调用方。
- 不改动跟踪号前缀分流规则。
- 不恢复旧版中文首页输入框查询流程作为主流程。

## 查询流程

查询地址：

`https://t.17track.net/en#nums=<tracking_no>`

流程：

1. 规范化跟踪号。
2. 打开新版英文直达页。
3. 等待页面中的时间线节点 `span.yq-time` 出现。
4. 读取时间线容器 HTML。
5. 提取每条轨迹的：
   - `时间`
   - `内容`
6. 若未提取到轨迹，则返回结构化错误。

## 解析规则

每条轨迹结构中：

- 时间节点：`span.yq-time`
- 内容节点：相邻的 `span.flex-1`

返回顺序保持页面顺序。

## 错误处理

- 页面长时间未出现 `span.yq-time`：
  - 返回超时错误
- 页面出现验证码或人工验证：
  - 维持当前已有等待与日志逻辑
- 页面出现但未提取到任何轨迹：
  - 返回 `17TRACK 页面未返回轨迹信息`

## 测试

- 解析测试覆盖用户提供的新版时间线 HTML。
- 原有 `tracking mode` 路由测试保持不变。
