# USPS 跟踪号查询接入设计

## 背景

当前跟踪号查询模式已经具备前缀分流能力，数字 `9` 开头会路由到 `usps`。

但 `usps` 仍是占位实现，尚未接入真实页面抓取。

与 `uniuni`、`gofo` 不同，`usps` 的数据可以直接从详情页中的状态步骤块读取，不需要登录，也不需要导出文件。

## 目标

- 对数字 `9` 开头的 USPS 跟踪号执行真实页面查询。
- 直接访问带跟踪号参数的详情页。
- 抓取页面中的所有 `tb-step` 状态块，而不是只抓当前状态。
- 把主状态、详情、地点、时间转换成统一轨迹结构。
- 返回最新状态和历史状态。

## 非目标

- 不实现 USPS 之外平台的真实抓取。
- 不改造单聊业务选择状态机。
- 不对 USPS 页面时间做复杂时区换算。

## 页面访问策略

直接访问：

`https://zh-tools.usps.com/tracking/<tracking_no>`

原因：

- 已知该链接可直接打开对应追踪结果页。
- 不需要额外输入框和搜索按钮。
- 更适合自动化。

## 查询流程

1. 规范化输入跟踪号。
2. 打开：
   - `https://zh-tools.usps.com/tracking/<tracking_no>`
3. 等待页面加载完成。
4. 定位所有 `tb-step` 状态块。
5. 逐个提取主状态、详情、地点、时间。
6. 组装为轨迹列表。
7. 返回统一结果结构。

## 页面识别规则

每条轨迹对应一个 `tb-step` 区块。

当前已知区块内可能包含：

- `tb-status`
  - 示例：`USPS 等待物品`
- `tb-status-detail`
  - 示例：`寄件标签已创建`
- `tb-location`
  - 示例：`HOUSTON, TX 77041`
- `tb-date`
  - 示例：`2026 年 06 月 08 日 3:40 下午`

其中：

- 当前最新状态通常带有 `current-step`
- 历史状态可能没有 `tb-status`，只有 `tb-status-detail`
- 历史状态的地点可能为空

## 字段映射

### 内容

建议映射规则：

- 若 `tb-status` 和 `tb-status-detail` 都有值：
  - `内容 = <tb-status> - <tb-status-detail>`
- 若只有 `tb-status-detail`：
  - `内容 = <tb-status-detail>`
- 若只有 `tb-status`：
  - `内容 = <tb-status>`

示例：

- `USPS 等待物品 - 寄件标签已创建`
- `发送给 USPS 的寄件前信息`

### 地点

- 直接取 `tb-location`
- 若为空则保留空字符串

### 时间

- 直接取 `tb-date` 原文
- 不强制转换为别的时间格式

原因：

- 页面当前输出已经是清晰的中文时间
- 先保证稳定抓取，后续如有必要再做标准化

## 轨迹顺序

页面顺序默认视为最新在前，按页面出现顺序保留。

因此：

- `物流轨迹` 保持页面顺序
- `最新轨迹` 取第一个有效 `tb-step`

## 返回结构

沿用当前统一结构：

- `平台: USPS`
- `查询值`
- `物流轨迹`
- `最新轨迹`

示例：

```json
{
  "平台": "USPS",
  "查询值": "9214490411372861932437",
  "物流轨迹": [
    {
      "时间": "2026 年 06 月 08 日 3:40 下午",
      "内容": "USPS 等待物品 - 寄件标签已创建",
      "地点": "HOUSTON, TX 77041"
    },
    {
      "时间": "2026 年 06 月 08 日",
      "内容": "发送给 USPS 的寄件前信息",
      "地点": ""
    }
  ],
  "最新轨迹": {
    "时间": "2026 年 06 月 08 日 3:40 下午",
    "内容": "USPS 等待物品 - 寄件标签已创建",
    "地点": "HOUSTON, TX 77041"
  }
}
```

## 数据清洗

解析后应执行以下清洗：

- 去首尾空白
- 去掉空 HTML 标签残留
- 跳过四个字段都为空的无效步骤
- 对缺失字段保留空字符串，不丢弃整条有效轨迹

## 错误处理

### 页面无状态块

返回：

- `错误: USPS 页面未返回轨迹信息`

### 页面结构变化

若关键节点缺失或提取失败，返回结构化错误，不抛出未处理异常。

## 测试策略

### 单元测试

新增一个纯 HTML 解析测试，至少覆盖：

- 能从示例 HTML 中提取 2 条轨迹
- 第一条为当前状态
- 第二条只有 `tb-status-detail` 时仍可保留
- 地点为空时不报错

### 路由测试

保留或新增分发测试：

- 数字 `9` 开头路由到 `query_usps_tracking`

## 风险

- 页面 class 结构可能调整。
- 部分状态块字段并不完整。
- 页面可能有异步加载延迟。

## 风险应对

- 依赖 `tb-step / tb-status / tb-status-detail / tb-location / tb-date` 这些相对稳定的 class。
- 解析时允许字段缺失。
- 页面加载后增加明确等待，再抓 HTML。
